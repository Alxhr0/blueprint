# Running a local Gentoo bootc system

Blueprint **no longer builds or publishes a Gentoo image**. If you want a Gentoo
bootc system, build it yourself and run it locally using the files already in
this repo. This guide walks through that end to end.

You end up with a bootable Gentoo system installed from an OCI container image
via [bootc](https://bootc-dev.github.io/bootc/). No prebuilt image is pulled
from `ghcr.io`; everything is built and installed on your machine.

## Prerequisites

- A host with `podman` (rootful or rootless — BIB needs privileges).
- `bootc` installed on the host if you want to install straight to a disk
  (`bootc install`). On Fedora/Ubuntu/Arch you can install the `bootc` package,
  or run it from a container.
- `bootc-image-builder` (BIB) for producing a VM/disk image:
  `quay.io/centos-bootc/bootc-image-builder:latest`.
- For a VM: `qemu`/`qemu-kvm` and KVM access.
- For bare metal: a target block device (whole disk).
- This repository cloned, so you have the root `Containerfile`, `build_files/`,
  and `system_files/`.

## Step 1 — Build the Gentoo container image

The image is built with Podman from the unified root `Containerfile`, passing
`VARIANT=gentoo` (and the matching base image). It uses a `gentoo/stage3:systemd`
base, pulls in Portage and a binhost, emerges the bootc/ostree/kernel/dracut/Podman
stack, and configures the bootc prepare-root and tmpfiles drop-ins.

```bash
git clone https://github.com/huntedraven7/blueprint
cd blueprint

podman build \
  -f Containerfile \
  --build-arg VARIANT=gentoo \
  --build-arg BASE_IMAGE=gentoo/stage3:systemd \
  -t localhost/gentoo-bootc:latest \
  .
```

Notes:

- The build copies `build_files/` and `system_files/` into a `scratch` context
  stage and applies them during the `system` stage. You must run the build from
  the repo root (the `.` at the end matters).
- `~amd64` (unstable) keywords and the Gentoo binhost are enabled, so the build
  pulls binary packages where possible. A full build can take a while and needs
  network access to `distfiles.gentoo.org`.
- The resulting image is tagged `localhost/gentoo-bootc:latest` and is
  **bootc-ready** (`LABEL containers.bootc 1`, `prepare-root.conf`, initramfs
  generated by dracut).

If you only want to tweak the package set, edit `build_files/base/build-gentoo.sh`
(the `PACKAGES` array) and rebuild.

## Step 2 — Install it

Pick one. Both install the *same* container image; only the target differs.

### Option A — VM disk image with bootc-image-builder

Produce a `qcow2` (or `raw`/`iso`) you can boot in qemu:

```bash
sudo podman run --rm --privileged \
  --security-opt label=type:unconfined_t \
  -v /var/lib/containers/storage:/var/lib/containers/storage \
  -v "$PWD/output":/output \
  quay.io/centos-bootc/bootc-image-builder:latest \
  --type qcow2 --rootfs=btrfs --use-librepo=True \
  localhost/gentoo-bootc:latest
```

BIB reads the image from your local Podman storage (mounted above) and writes
`output/disk.qcow2`. Boot it:

```bash
qemu-system-x86_64 \
  -m 8G -smp 4 -enable-kvm \
  -device virtio-net-pci,netdev=net0 -netdev user,id=net0,hostfwd=tcp::2222-:22 \
  -drive file=output/disk.qcow2,format=qcow2,if=virtio \
  -nographic
```

Then `ssh -p 2222 root@localhost` (or use the console). `systemd-networkd`,
`systemd-resolved`, `sshd`, `iwd`, and `chronyd` are enabled in the image.

> Optional: pass a BIB config with `-v "$PWD/disk_config/disk.toml:/config.toml:ro`
> and `--config /config.toml` to set users/SSH keys/disk layout.

### Option B — Install straight to a disk (bare metal)

Use `bootc install` to lay the image onto a block device as an ostree/bootc
sysroot:

```bash
# Wipe and install to a whole disk (DESTRUCTIVE — double check the device)
sudo bootc install to-disk --target-img /dev/sdX localhost/gentoo-bootc:latest
```

For a VM disk file instead of a physical disk, create a qcow2/raw, attach it as
a loop device, and point `to-disk` at the loop device. Reboot into the device
and you have a native Gentoo bootc install.

## Step 3 — First boot & updating

- Login is `root` (no password by default in this image — set one or drop in an
  SSH key before installing; see a BIB config or `system_files/global`).
- Portage works as normal: `emerge`, `eselect profile`, etc. Because bootc
  makes `/usr` read-only at runtime, install packages into the image by
  **rebuilding the container image** (Step 1) and re-installing — not by emerging
  on the running system. Treat the running system as immutable.
- Update the OS: `bootc upgrade` (pulls a newer built image and stages it as a
  new deployment; reboot to apply). Roll back with `bootc rollback`.

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| Build fails pulling `gentoo/stage3` / `gentoo/portage` | Network/proxy, or registry rate limit. Retry; or pre-pull the bases. |
| `bootc install` says image not found | Use the full ref (`localhost/gentoo-bootc:latest`) and ensure it's in root's Podman storage (`sudo podman images`). |
| BIB can't find the local image | BIB reads from mounted `/var/lib/containers/storage`. Run BIB as `sudo` and mount the storage volume as shown. |
| System boots to emergency/ostree | Dracut initramfs missing for the running kernel, or `prepare-root.conf` absent. Rebuild the image (Step 1 regenerates the initramfs). |
| `/usr` is read-only after boot | Expected — bootc makes `/usr` immutable. Change the image, not the running system. |

## Scope

This is a self-supported, local workflow. Blueprint's CI does not build, push,
or sign a Gentoo image, so there is no `:gentoo` tag on `ghcr.io` to track.
Build it, install it, own it.
